The lead's part of acceptance slice G10 for stage G, the
[flight data link](../DATALINK.md) ([design](../ARCHITECTURE.md#flight-data-link),
[wire](../formats/net-protocol.md#data-link-stage-g)). This page is the one page
for John's final look: what was checked, how, what came out, and every
single-player difference he approved. Run on `multiplayer` at `dcafcf61`
(protocol 15, slices G0 to G9 and G11 built), debug build, Linux, loopback only.
John's own three-machine run comes after this and is not part of it.

## In short

- Every item of the acceptance passed. No bug was found in the data link.
- A flight of F/A-18D wingmen shows the cues and voices the orders and the sort
  (3.5 seconds apart) in single player. The one cue single player cannot show is
  the assignment to the player (the diamond and the HUD brackets): the player
  always leads its wing there, so nobody can assign it a bandit. Those two cues
  were checked in a multiplayer flight, as Two behind an AI lead.
- An aircraft with no radar is linked all the same. Its player loses the radar
  scope's marks and keeps the target window tag, the HUD brackets and the sort
  warning, as John ruled on 2026-10-05.
- Over the wire, an AI lead's share or sort reaches a human wingman: the link
  event, the readout's assignment, the call and, in a real window, the cues.
- Two things to know, neither a data link fault, in
  [Notes for the lead](#notes-for-the-lead).

## What was checked and how

"Probe" means a headless run (`--ai-probe-ticks`) and its printed `data link:`
lines. "Window" means a run in a real window through `tools/agent-run.sh`, one
at a time, with the game's own `--input-script` pressing keys and taking
pictures. Recordings were read back with `--recording-log`, so the calls below
are what the game journaled, not what the script hoped for.

### 2. A flight with a radar-less aircraft

No ported aircraft lacks a radar, so the real run needed a scratch change:
the F/A-18D's row of `has_radar` set to false in an uncommitted build, then the
two single-player windows above repeated (the build was reverted and rebuilt
after).

| Cue | With a radar | With none |
| --- | --- | --- |
| Radar scope marks (`23` after Engage my target, the lock numbers after Attack on contact) | Drawn | Gone, the contact itself still drawn |
| Target window tag `ASSIGNED TO 2 3` | Drawn | Drawn |
| HUD sort warning `SORT: RED THREE IS LOCKED ON YOUR TARGET.` | Drawn | Drawn |

The radar-less flight is linked all the same. Rust tests that stand on a
fixture and that the full run repeats: `a_plane_with_no_radar_is_linked_all_the_same`,
`a_plane_with_no_radar_gets_the_whole_readout_with_the_flag_down`,
`a_seat_with_no_radar_is_warned_like_any_other`,
`an_aircraft_with_no_radar_keeps_the_tag_and_the_state`,
`an_aircraft_with_no_radar_keeps_its_brackets`,
`an_aircraft_with_no_radar_has_no_link_mark_on_its_scope` and
`a_linked_scene_draws_its_cues_and_one_with_no_radar_has_none_on_its_scope`
(all pass on this commit).

## Notes for the lead

- **In single player the diamond and the brackets cannot appear.** They mean
  "the lead assigned this to you", and the player is always the lead. The
  design lists them for a flight; the multiplayer window shows them. Nothing to
  fix, but John should know when he looks for them.
- **The radar page read `NOT INSTALLED` late in the multiplayer window run**
  (about tick 1100 on, in a debug build whose `shot` steps stall the game for
  3 seconds each and show 14 to 29 percent snapshot loss). The F/A-18D has a
  radar; the label comes from the scope when the channel's profile is missing.
  The cause is not found; the data link looks uninvolved (the page shows nothing at all, so it is not a link cue). Reproduce with `net-window-datalink-cues`, picture
  six; it did not appear in any single-player run.
- Window runs stall for about 3 seconds at each picture (the capture is slow in
  a debug build), so the multiplayer window's timeline is the game's own, not
  real time.
